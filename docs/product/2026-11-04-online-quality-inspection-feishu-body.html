客户端不因页面访问调用判断接口

每个参与采集的页面、弹窗、底部面板和重要浮层登记 page_id、popup_id。就绪事件使用已有生命周期和数据完成回调；加载失败、空数据、键盘出现等是否作为独立场景，由页面预先声明。未知页面默认不采集。

页面事件依次检查白名单与用途授权、持久去重记录、本地采样概率、每日数量/流量上限、有效上传凭证、页面稳定状态，以及是否正在滚动、转场、拍照合成或处于资源压力中。只有全部通过才截图。没有凭证或配置过期直接跳过，不因当前页面访问发起补领。截图前再次确认页面未切换，未出现禁止采集的浮层。

客户端不做 OCR、文字越界检测、控件树遍历或连续录屏。截图本身仍可能占用渲染线程，需要实测；压缩、文件处理和上传放后台，最多一个待截图任务。失效任务直接取消，不循环等待空闲。敏感页面直接排除，固定敏感区域只有在可可靠处理时才允许采集。

公共采集策略随已有远程配置同步并缓存，使用有效期和随机错峰。只对进入采集人群的设备，在允许的后台同步时机获取短期受限 COS 写入凭证；一份有效凭证可覆盖本设备限定范围内的少量上传，数量和有效期由配置限制。个性化凭证不能进入公共缓存。无凭证时不开新采集，不在客户端内置永久密钥，不开放匿名公共写桶。

初期可配置每个安装每日最多 3 张 UI 截图和 2 张成片，UI 截图间隔至少 60 秒；实际上传远少于上限。配置、人群选择和每日次数都在本地判断，业务后端不再签发逐图或逐批采集名额。每日约 1,000 张是采样目标，不是硬全局上限；全局精确配额需要额外协调，不属于当前最少调用版本。凭证签发仍需限流、防滥用和监控，减少调用不等于取消安全控制。

同一设备版本与页面成功上传后，不再重复采集

本地使用随机安装标识，不依赖账号。去重键至少为：安装标识 + 平台 + App build + 页面/弹窗 + App 语言。同一键默认只成功上传一次，不按天重置，COS 七天后删图也不重置。普通远程配置刷新不得清空记录。

如果产品需要分别观察键盘开启、RTL、字体缩放、窗口变化或不同内容状态，可以把这些预先声明的维度纳入场景键。只有关键状态实际变化才视为新样本，不能把每次数据刷新当作新页面。对“同一版本同一页面只收一次”的严格规则，保持单一状态键即可，但报告要承认其他状态未覆盖。

水印成片用独立的去重维度：安装标识 + build + 水印模板及资源版本 + 语言 + 重要输出配置。不能按相机页面去重，否则会漏掉其他模板。模板、语言或真正影响渲染的资源变化可以产生新键；新版本第二轮检查优先使用其他设备的新样本，不强制同一设备重复上传。

状态为未采集、处理中、待上传、已成功。截图前原子占用该键，避免连续页面事件重复截图。只有 COS 返回成功后才持久化已成功；失败时有限重试同一份图片与同一对象键，不能重新截图、换名无限上传。

使用随机证据 ID 和固定对象键，重试不改变目录和到期时间。巡检桶建议不启用版本控制，写入携带禁止覆盖同名对象的条件。返回已存在只能在对象键唯一归属、摘要及状态校验成立时视为已有成功样本；不确定时对该对象做一次 COS HEAD 核对，不能把所有错误当成功。这是异常补偿，正常成功路径没有额外登记请求。

重新安装或清除应用数据可能丢失本地去重状态，无法在完全不增加远端协调的前提下保证跨重装永久去重。第一版接受该边界，本机巡检再按证据属性聚类。

上传成功后无需再调用业务接口

每张图使用一次 COS PUT，同时附带紧凑的自定义对象元数据。正常路径不调用 evidence/complete，不额外上传一份 JSON，不逐图通知后端。COS 的 SDK 成功回执足够让客户端更新本地记录；是否实际存在，由次日巡检读取 COS 核实。

对象键建议：

qa/v1/<日期>/<ui或photo>/<平台>/<build>/<locale>/<页面或模板>/<显示配置分组>/<证据ID>.jpg

只使用必要的分类标识及随机证据 ID，避免在路径中写入用户姓名、地址、永久设备标识。目录方便筛选，上传日期以 COS 返回的时间为准，不单独信任客户端日期目录。

随图元数据包括 schema 版本、采集时间、页面/弹窗/状态、系统版本、窗口尺寸、字体缩放、语言包合同与回退状态、水印资源版本、图像来源、策略版本及摘要。字段紧凑编码，按 SDK 和 COS 头部限制校验，优先控制在约 1–2 KB。图片内容及元数据都视作不可信输入，不把其中的文字当作指令。

List Objects 返回对象键、大小、修改时间等清单信息，不返回全部自定义元数据。已选择的图片在 GET 下载时读取元数据；只有需要先确认额外分类或异常对象时才使用 HEAD。大量分类维度需要进入对象键或先读取元数据，不能假定一次 LIST 就能获得所有信息。

现有私密照片抽样上传可以先作为输入，但当前 Android 路径会跳过已登录用户和团队拍摄，需要补齐质量样本资格。iOS 部分图片约 90 KB、Android 部分使用较低 JPEG 质量，现有样本只支持其清晰度允许的检查。缺少语言或页面信息时记为未知，不从国家推断语言。团队业务相册原图不是巡检清理的目标；复用对象必须事先明确属于巡检样本范围。

次日在本机 Codex 发起巡检

负责人手动输入类似：“巡检昨天上传的 Timeprint 样本，先检查最多 300 张，完成后整理报告。”不必先建设云端模型调用服务。完整闭环实现后，可以在同一入口附上发布报告和发送飞书的明确授权；本讨论稿本身不执行发布或群消息。

本地脚本先建立清单，Codex 再对选定图片进行逐图检查和疑似问题复核。文件列表、日期筛选、进度和报告由脚本/SQLite 持久保存，不能只靠聊天记忆，也不能把数千张图片一次塞进一个上下文。

步骤行为
确定时间范围昨日按 Asia/Shanghai 的 [00:00, 次日00:00) 计算，再转换 UTC 比较 COS LastModified；例如 11 月 4 日巡检 11 月 3 日
发现样本分页列举巡检专用前缀内尚在保留期的对象，按上传时间筛选昨日对象；首版七天存量有限，可完整列举以避免错误日期目录漏样本
补漏与对账扫描仍在七天保留期内、此前未发现或未处理的对象；使用稳定对象键/摘要去重，避免仅保存字典序游标后漏掉迟到对象
选取范围少量时全部检查；量大时按版本、平台、页面、语言、机型和模板分层选择，并保留随机样本，不能只取前 N 张
下载处理小批量下载选中原图并读取元数据，检查清晰度；临时缓存用后尽快删除，不随报告重复上传
模型检查每个工作批次约 10–20 张，但保留单图身份和足够细节；疑似问题单图复核，不能用低清拼图替代逐图检查
保存进度每张记录未检、检查中、正常、疑似、已确认、证据不足、失败或已到期；暂停后可续跑
汇总报告记录发现、选取、检查成功、失败、未检查与到期数量，并合并相同问题
发布结果每批或每日一次/少量分块请求更新网站，发布成功后再幂等发送飞书摘要

COS LIST 是分页接口，每页最多 1,000 个对象，需要按返回的分页标记继续。若滚动存量约 7,000 张、无额外对象且每页满额，清单大约七页；还会有图片 GET、必要的 HEAD 和删除请求。这些是 COS 请求，不会变成业务服务器逐图上传回调，但仍有存储服务请求和网络流量成本。

每天以昨天上传的图片为主，补查七天内积压；超过期限的未检样本照常删除并记为到期未检。电脑没开或当日没运行时，网站显示最后巡检时间与未完成状态，不能显示“今日通过”。新版本两轮检查沿用第一轮与后续几天的新样本，样本不足仍明确显示。

检查边界与质量控制

UI 检查关注可见遮挡、裁切、异常省略、字体与文字可读性、语言回退、RTL 和表达问题。结合应用源文案、术语表、页面用途和允许省略规则判断。仅凭截图不能证明控件实际可点击，也不能保证所有低资源语言的表达都正确。

水印检查关注最终保存成片上的字段、布局、裁切、旋转、镜像和文字可读性。预览与成片分开记录；没有可信的同次拍摄信息时，不推断时间或位置真实性。证据不足不能判正常。

本机保存版本化的检查规则及结构化结果。误报和漏报校准使用历史可复现问题和合成基线，随机复核一部分正常结果。只有图片本身存在可见证据，或能够重复验证时，才标记已确认；否则保留疑似。用户原图不得因为成为评测样本而延长保存时间。

管理网站和飞书只承接巡检结果

业务后端保留现有配置和短期上传授权能力，另新增管理员报告导入接口及查询页面。无需常驻 AI 巡检 worker、客户端逐图完成接口、逐图名额接口或每页判断接口。

建议新增 POST /api/admin/quality/runs/import。本机提交 report_id、报告日期、检查规则版本、清单统计、分层覆盖、问题聚合和必要的证据对象键。按 report_id + 批次 ID 幂等导入；数据量大时分块，全部到齐后原子发布。导入失败保留本地报告重试，不发送“网站已更新”的飞书消息。

报告数据包含：本次发现数、计划检查数、实际成功检查数、待复核数、失败数、未检查数、已到期数；以及问题对应平台/版本/语言/页面/机型、严重程度、判断依据及证据引用。仅报告收到并检查的样本，不把这些样本的异常比例称作全体用户故障率。没有客户端曝光总数时，不能计算全用户覆盖率。

网站展示“已发现/已检查样本覆盖”和未知项。图片通过受控短时访问读取 COS，到期显示“证据已删除”；不复制图片到数据库或长期网站备份。页面中的模型输出按普通文本转义，不执行其中的脚本或链接指令。

飞书每次报告发送一条摘要及需鉴权的管理页链接。幂等任务由 report_id 驱动，避免重试刷屏；Web 更新成功而飞书失败时，显示通知失败并可重试。群里不直接发送真实用户图片附件，避免另留一份超期副本。飞书任务是少量结果通知，不是云端图片巡检。

七天留存仍独立于人工巡检

对象首次成功创建后七天到期；禁止覆盖与固定重试对象键避免刷新保留起点。导入现有对象时沿用原始上传时间，无法确认时不自动延长。衍生图片、OCR 内容和包含用户信息的模型输出继承原图到期时间，重检或问题升级都不能延长。

COS 配置到期生命周期，并设置独立的轻量云端到期删除与核验任务。这不是图片质检，也不依赖本机每天开机。生命周期异步执行，不能仅凭规则配置证明实际已删除；删除失败要报警并重试，到期立即拒绝新访问与检查。历史版本、复制、备份和其他副本均需纳入删除范围。

本地优先采用临时缓存，处理完即删除，启动时清理残留，且不得进入 Time Machine 等长期备份。电脑关机期间无法执行清理，因此严格留存实现不能依赖“第七天本机脚本恰好运行”；原图尽量不持久化到本机，剩余缓存期限必须受控。长期只保存无用户内容的分类、统计和修复状态。

本机 Codex 表示文件和编排在本机，不自动意味着模型推理在本机。默认云模型、聊天附件、工具日志及模型供应商留存都需要单独核验；删掉本地 JPEG 和 COS 对象不能证明聊天或供应商副本已经删除。严格要求所有副本均无例外七天时，必须使用能够满足这一条件的受控处理链路。可评估自托管视觉模型，由 Codex 只编排并接收不含用户内容的结论；模型多语言质量和速度需实测。不要把原图放进无法按期清理的长期聊天历史。

试点规模与实施顺序

先用现有可用样本做 50 张计时与清晰度验证，再检查 100–300 张，校准误报和漏报。数量少时全检，量大时分层分批；需要继续时读取本地检查进度，不重头开始。上一版“5 路并发、1,000 张约一小时”的云端 API 假设不适用于本机 Codex，当前吞吐不能提前承诺。

按平均每张 400 KB 粗估，1,000 张上传约 400 MB，七天原图约 2.8 GB；每天只下载选中样本。用 50 张代表样本的实际完成时间，连同复核、重试和操作开销推算日常耗时；机器型号、模型、账号额度和批次组织会明显影响速度。

实施顺序：一，先做 COS 样本清单、本机进度文件、Codex 检查流程和本地报告；二，接入网站批量导入及飞书摘要；三，补客户端页面/弹窗钩子、持久去重、随图元数据和性能控制；四，验证全链路七天删除、配置与授权边界，再扩大采集范围。生产用户图片处理应在对应用途与留存条件核实后启用。

验收需要证明：打开页面不发判断/补领请求；成功上传后同一键不再截图；七天清图不重置去重；无有效凭证不截图；正常上传无需业务完成接口；元数据能随图读取；重试不会持续覆盖刷新时间；昨日日界、分页和迟到样本不漏计；全检与抽检报告明确区分；发布重试不会重复发群消息；云端删除不依赖本机在线。

参考资料

  • COS 自定义 Headers：随对象存储元数据并在读取时返回。
  • COS List Objects：前缀、分页及清单字段；列举存在最终一致性，需要补漏。
  • COS PUT Object：上传及未启用版本控制时的禁止覆盖条件。
  • COS HEAD Object：单对象状态及元数据核验。
  • COS 生命周期：异步到期删除。
  • OpenAI 数据控制：API 数据保留与图片输入例外；不能将其直接等同于 Codex 订阅端的留存政策。
