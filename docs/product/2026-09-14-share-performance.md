# 三类公开分享页：大图库性能与选择稳定性

已在本机实现并验证。线上尚未发布。以下时间是本机 MySQL + Next.js 开发服务、编译完成后的热请求，不代表线上首屏、弱网或所有手机的性能。

## 修复的问题

上一版只限制浏览器每页渲染 48 张，服务端仍读取、格式化、序列化全部照片。照片增加时，首屏数据和浏览器筛选的成本随总数增长。

现在项目、个人、团队三个页面共用真正的服务端分页：首屏最多 48 条，页面直接复用首屏数据；翻页通过局部请求替换照片区域，保持同一个 React 页面，不调用路由整页刷新。浏览器最多缓存 6 页，并预取相邻下一页。元数据筛选列表单独读取。

搜索在输入暂停 250 ms 后发出请求。新请求开始时取消旧请求，并校验请求序号，避免迟到的结果覆盖最新筛选。加载期间旧内容保留，照片操作区暂时禁用并显示状态；失败提供重试，选择状态不依赖请求结果，不会因为加载失败被清空。预取失败不会让已加载的页面进入错误状态。

勾选独立于当前页保存：翻页、切换视图、关闭预览、改变排序都保留选择。全选使用“全部符合条件的照片－排除项”，不会把一万个 ID 或完整照片下载到浏览器。导出时由服务端解析筛选与排除条件，继续验证公开链接范围和数量限制。修改筛选条件会主动清空选择，避免导出旧条件下的照片。选择是当前页面会话状态，手动整页刷新不承诺保留。

浏览开始时固定 createdAt 时间边界，后续分页和导出沿用该边界，新上传照片不会挤动当前页。该边界不是数据库 MVCC 快照，已有照片的删除、时间或权限修改仍以服务端现状为准。

地图按需加载地图组件、底图和当前页最多 48 张照片的位置；地图页仍可翻页，并明确显示“地图显示当前页照片的位置”。这避免一次创建成千上万个标记。图片懒加载，卡片有固定比例；底部缩略图只渲染当前窗口。日期格式器/时区校验使用有上限的缓存。

复制的大图链接可按 photo ID 单独查询，并找到其所在页，不需要把之前的所有页面下载一遍。

## 一万条记录测试

使用独立本地团队 `local-share-perf-10000`、用户 `local-share-perf-user`、10000 条测试照片资料，图片复用本地测试插图，不涉及线上数据。

| 范围 | 第 1 页 | 第 2 页 | 第 100 页 | 第 209 页 |
|---|---:|---:|---:|---:|
| 团队 | 119 ms | 148 ms | 140 ms | 134 ms |
| 项目 | 123 ms | 114 ms | 125 ms | 129 ms |
| 个人 | 121 ms | 123 ms | 135 ms | 124 ms |

- 满页每次 48 条，JSON 约 29.5 KB；末页 16 条约 9.9 KB。
- 首屏 HTML 实测约 103 KB，只包含首屏照片，不含第 10000 张的资料。HTML 数值不含 JS、字体和图片下载，不能当作整页传输大小。
- 日期 + 地点组合筛选：101 ms，匹配 420 张，每页仍最多 48 条。
- 页码不重叠；新增一条更晚上传照片后，固定时间边界的分页总数和首屏 ID 不变；重新打开的新请求可以看到新增照片。测试新增记录已删除。
- 第 10000 张照片的深链接定位第 209 页通过。
- “全选 5000 张结果，排除 1 张”实际生成 Excel，读回文件验证 4999 条，排除的照片不存在于文件中。

## 浏览器检查

在 10000 张图库实际操作：第一页选择第 1 张 → 第二页选择第 49 张 → 返回第一页 → 打开/关闭预览，始终保留 2 张选择；导出弹窗默认“已选照片 (2)”，实际 Excel 下载成功。

局部照片卡片数量始终为 48。连续 8 次上下滚动样本中，可见诊断面板的长任务计数未增加，帧间隔 P95 约 10 ms。这里是桌面、本地图片样本，不是低端手机、真实 COS 大图、弱网或持续压力测试，不能承诺任何设备绝不卡顿。

快速连续填写三个搜索值，只增加最后一次搜索与下一页预取的两个数据请求。复用首屏后，第一页→第二页→第一页完整流程观察到 3 个 list 请求（筛选列表、第二页预取、第三页预取），首屏未重复请求，返回第一页命中缓存。

`?perf=1` 可在本地开发模式显示可见性能诊断面板。正常链接及生产构建不会显示。

- `npm run build` 通过。独立 TypeScript 检查本次文件无错误；仓库原有旧 App API/管理页类型错误仍存在。

性能脚本仅允许连接本机 `tp_team_backend_local`，测试团队保留以便后续复查。结果原始 JSON：`.local/share-performance.json`。

更大规模仍使用 offset 分页，搜索 contains 不具备全文索引优势。当前一万条测试表现稳定；十万/百万级数据、跨地区网络和高并发仍应另做数据库与 CDN 压测，必要时改为游标分页、搜索索引及独立导出队列。
