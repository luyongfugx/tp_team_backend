# 工作区 ZIP 下载回退修复

## 原因

线上导出弹窗报“加载失败，请重试”。在部署平台应用日志中确认，创建后台导出任务时 `prisma.workspaceExport.count()` 报 P2021：数据库缺少 `WorkspaceExport` 表。旧页面的 `/api/admin/team-photos/download` 本来就能同步生成 ZIP；新工作区改用后台任务，却没有保留未迁移部署的可用下载路径。

## 修复

- 默认通过 `/api/workspace/photos/export` 打包并直接下载，无需导出任务表、独立 worker 或持久导出磁盘。旧下载接口保留。
- 延续工作区筛选、全选排除项、成员权限、数量核对和拍摄时区；支持拍摄人、项目、日期目录。文件编号防止同名覆盖。提交和打包结束都核对访问范围。
- 同步下载最多 200 个文件、源文件合计 100 MiB，每进程同时最多 2 个打包请求，240 秒总超时。全部文件读取成功才返回 ZIP，失败不会悄悄漏图；选择状态保留，便于重试。慢速大文件需分批或启用后台导出。
- 下载来源沿用现有配置的 COS 桶；自定义 CDN 仍需加入 `WORKSPACE_MEDIA_HOSTS`。不接受任意远程下载地址。
- 缺任务表时导出记录返回空记录和不可用标记；后台提交返回明确的 `EXPORT_SERVICE_UNAVAILABLE`，不再笼统显示加载失败。
- `WORKSPACE_BACKGROUND_EXPORTS` 默认关闭。完成迁移、worker 和共享导出目录配置后才设置为 `1`，启用原有 2,000 文件 / 2 GiB 后台任务模式。

## 部署

普通 ZIP 下载只需部署新代码，保持 `WORKSPACE_BACKGROUND_EXPORTS=0`（或不设置）及现有媒体存储配置。没有改动登录、二维码登录、旧 ZIP 下载接口或现有数据库表结构。

需要后台导出时，按 `2026-09-14-predeploy-review.md` 的迁移及 worker 部署步骤完成配置，验证 worker 可完成任务后，再给网页服务设置 `WORKSPACE_BACKGROUND_EXPORTS=1`。两种模式的记录区别已显示在界面：直接下载的 ZIP 保存在用户设备，仅后台导出显示任务记录。

## 验证

本地专用数据库运行：

```sh
node --env-file=.env --import tsx scripts/workspace-direct-export.integration.ts
```

依赖本地工作区和 10,000 照片性能测试 fixtures，以及 `127.0.0.1:3000` 开发服务。测试创建的会话、临时大文件和照片 URL 修改均在结束时清理/恢复；模拟缺表只替换测试进程的 Prisma 方法，不删除或改名数据库表。

已验证：12 文件 ZIP 的真实生成、解压和 CRC 校验；三种分组；任务表缺失时仍能生成 ZIP；明确后台错误；未登录与成员权限；筛选后全选排除；选择数量变化；无效参数；源文件缺失时整包失败；200 文件和 100 MiB 边界；真实 Next HTTP 下载与默认模式标记。

生产构建通过；工作区、公开图库和会话的 15 项单元测试通过；原后台导出集成回归通过，覆盖 22 文件 ZIP、租约恢复、取消、部分失败重试、权限变化及过期下载。`tsc --noEmit` 仍有仓库原有的 21 项类型错误，本次修改的文件无新增类型错误；构建配置原本跳过类型检查，因此不能将构建通过等同于全仓类型检查通过。

线上仍需部署本次修复后，以真实 COS 照片和视频复测下载。此处本地结果不代表线上已更新。
