# Timeprint TeamSpace 改造建议：与 Timemark 的实站对比

调研日期：2026-09-14。依据：Chrome 中已登录的两个网站，以及当前 `tp_team_backend` 仓库。本文为产品与实施建议，未修改业务代码。

**产品能力更正：用户已明确，Timeprint 当前没有照片验真功能。此前将旧界面/代码中的入口视为可用能力是错误判断。验真不属于本轮改造范围，也不应作为现有功能宣传。**

**建议把 Timeprint 的主流程调整为：进入工作区 → 找到项目或成员 → 筛选照片 → 检查拍摄记录 → 导出或分享。**

我们已有团队、项目、成员、日期图库、大图预览、拍摄信息和 ZIP 下载，可以沿用。改造重点是入口组织、跨页面一致性和任务完整性。保留 Timeprint 品牌与拍摄记录展示。

## 1. 实际浏览范围与证据边界

| 产品 | 已浏览的页面与状态 |
| --- | --- |
| Timemark | 所有照片；项目卡片列表；项目照片、表单、文档标签；创建项目及更多选项；CompanyCam 导入入口；成员卡片列表及成员照片；图库与表格切换；日期快捷菜单；照片地图；照片台账表；单图大图、缩放、详情侧栏、当前照片/原始照片菜单；网页上传弹窗；侧栏 ZIP、Excel、PDF、KMZ 选图流程；PDF 编辑预览与元数据设置；分享配置弹窗；照片模板；表单模板；表单提交列表与详情；SharePoint、Google Drive、Webhook 页面；常用设置、成员与权限、方案与账单 |
| Timeprint | 我的团队；普通成员所在团队与自己创建的团队；项目列表及项目照片；团队图库；成员列表及成员图库；大图与缩略图导航；拍摄记录；选择、全选、反选、全取消、批量下载入口；个人设置 |

来源入口：[Timemark 所有照片](https://teamspace.timemark.com/zh/allPhotos)、[项目](https://teamspace.timemark.com/zh/projects)、[成员](https://teamspace.timemark.com/zh/members)、[照片地图](https://teamspace.timemark.com/zh/photoMap)、[照片台账](https://teamspace.timemark.com/zh/photoSheet)、[Timeprint](https://teamspace.timeprint.net/)。Timeprint 当前大多数管理界面通过页面内部状态切换，网址仍为 `/`。

边界说明：

- 两站账号角色、照片内容及数量不同，不能用这次浏览结果比较加载性能，也不能把普通成员看不到的按钮直接判为功能缺失。Timeprint 自有团队的管理视图已另行查看。
- 实际尝试了 Timemark 项目内的 ZIP、Excel 下载，下载资源域名被 Chrome 以 `ERR_BLOCKED_BY_CLIENT` 拦截；没有绕过拦截，未核验导出文件内部内容。
- PDF 已进入编辑预览并查看配置，未执行最终下载；分享仅查看配置，未点击复制链接或发送分享；没有上传文件、创建项目、修改权限或连接第三方服务。
- Timemark 的表单模板页明确提示“表单仅在 App 中可用”；照片模板在当前团队显示引导空状态。不能据此认为其网页具备完整模板编辑器。
- Timemark 成员浏览页显示 2 人，但设置中的成员与权限页本次显示 0 成员、0 角色。该状态可能来自加载或产品异常，实际角色编辑能力未进一步核验。
- AI 仅观察了侧栏、统计和快捷问题入口，未向 AI 发送问题，未验证其回答质量。
- 未发现独立导出历史页；侧栏“分享 & 报告”下的几个格式入口主要打开照片选择器。下文的“导出中心”是给 Timeprint 的建议，不是对 Timemark 现状的描述。

## 3. 推荐的信息架构与具体交互

### 3.1 工作区外壳

左上角显示当前团队名，点击切换已有团队，并保留“管理团队”入口。当前团队的所有照片是默认页，记住最近访问的工作区。

首期主导航：所有照片、项目、成员、导出与分享、团队设置。地图和表格先作为照片页面的视图切换，减少一开始的菜单数量。个人资料与退出放在头像菜单中。平台超级管理员功能使用独立管理区域。

推荐路由示意：

```text
/workspace/:groupID/photos
/workspace/:groupID/projects
/workspace/:groupID/projects/:projectID
/workspace/:groupID/members
/workspace/:groupID/members/:userID
/workspace/:groupID/exports
/workspace/:groupID/settings
```

以上均为建议新增路由。搜索、日期、视图及照片编号写入可恢复的 URL 状态；刷新、浏览器前进后退和复制内部链接均应保持上下文。它们与无需登录的对外分享链接分开处理。

### 3.2 项目列表与项目页面

卡片优先解决“认出项目”和“知道最近有没有更新”：

- 封面优先使用最新一张照片；如果要达到 Timemark 的多图拼贴效果，再补最近三张缩略图查询。
- 主信息：项目名、最近更新时间、照片数量；次信息：成员数、地址；不要把创建时间作为主要活跃度指标。
- 整张卡片进入项目照片；右上菜单提供编辑、成员、导出等操作，不要求用户找小号“查看”按钮。
- 搜索项目名称，排序支持最近更新、名称、照片数量；无照片项目显示明确空状态。
- 项目内标题行下直接是照片操作与筛选条。项目介绍、详细地址和成员管理可放在“项目资料”侧栏。
- 首期不展示尚未实现的表单/文档空标签。

### 3.3 统一照片工作台

所有照片、项目照片、成员照片使用同一套组件和查询协议，仅初始范围不同。

典型流程：从项目进入 → 日期选择本周 → 成员选择两人 → 查看某张照片 → 关闭大图 → 保持原滚动位置与筛选 → 导出该范围。不要每一步都回到团队列表或清空筛选。

筛选建议：关键词、项目、成员、日期范围、照片/视频。关键词先覆盖现有文件名、位置、作者、项目和照片码，不宣称具备尚未实现的图像语义搜索。

多选分清三种范围：

1. 明确勾选的照片 ID。
2. 当前页的照片。
3. 满足全部筛选条件的照片，允许排除个别照片。

操作栏明确显示“已选 8 张”或“已选全部 1,248 张筛选结果”。换页保留同一范围的选择，改变工作区或核心筛选时明确重置。全选不能仅凭浏览器已加载的缩略图计算。

### 3.4 大图与详情

在桌面端，主图区域自动适应剩余空间，详情栏建议固定约 320–360px 并可收起。缩略图条可折叠，竖图尽量获得完整高度。实际尺寸需用 1366×768 与 1440×900 等常见屏幕验证。

交互要求：左右键切换、Esc 关闭、缩放后拖动、双击放大/恢复、显示当前序号、预加载相邻图、关闭后回到原位置。加载中、加载失败、无坐标、旧照片无照片码都要有对应状态。

详情字段分层：

1. 拍摄记录：作者、项目、拍摄时间。
2. 位置：地图、地址、经纬度、复制及导航。
3. 设备：设备型号、系统、时区。
4. 记录入口：照片码与查看记录。

当前不提供照片验真，不展示核验状态或“验证通过”标签。对于缺失的拍摄字段显示暂无信息。新增报告备注应与原始拍摄元数据区分。

### 3.5 导出与分享

统一操作为“选范围 → 选格式 → 配置 → 预览或确认 → 生成 → 下载”。项目内默认带项目范围，已选照片优先带选择集合。

| 格式 | 首期提供什么 | 必须说明什么 |
| --- | --- | --- |
| 单图 | 下载当前可用照片文件 | 下载内容是加水印版本还是独立原图；未保存原图时不展示虚假的选项 |
| ZIP | 目录分组、文件名规则、任务进度、失败列表 | 请求数量、成功数量、失败数量及文件过期时间 |
| Excel | 基础台账字段、时区、筛选范围 | 与屏幕结果使用同一权限和筛选；链接有效性不能依赖临时图片 URL |
| PDF | 报告标题、摘要、照片顺序、选定元数据、预览 | 缺失图片、缺失记录、页数、实际报告时间范围 |
| 分享 | 标题/备注、固定集合或持续更新、有效期、下载开关、撤销 | 谁可访问、范围是否会随着新照片变化 |

建议新增“导出与分享”页面，提供本人创建的任务与链接列表：排队、处理中、完成、部分失败、失败、取消、已过期；可以再次下载、重试失败项或撤销分享。它是改进建议，不是本次已确认的 Timemark 页面。

时区口径在日期筛选、图库分组、文件目录和报告中保持一致。若同时展示不同时区的照片，必须明确以工作区时区还是拍摄地时区组织。

## 5. 分阶段实施方案

### 阶段 A：统一规则与入口（P0）

交付：确定团队/项目/成员的读、下载、导出、分享权限；区分内部图库与公开分享；新增工作区路由和切换器；提取共享照片查询协议；修正全量查询分页。

验收：

- 管理者、普通成员、指定项目成员分别得到正确的照片数量与范围。
- 同一范围在图库、详情、下载中权限一致。
- 复制内部页面地址、刷新、浏览器返回能够恢复对应工作区及页面。
- 用固定大小的分页请求验证，数据库读取量不会随整个团队照片数线性增长；同一天大量照片也可分段加载。

### 阶段 B：图库体验第一版（P0）

交付：项目/成员卡片；紧凑的项目预览；关键词、成员、日期、类型筛选；多选操作条；改进的大图与详情；基本地图定位。

验收：

- 从项目列表单击项目即看到照片。
- 进入“选择”默认选中 0 张；日选择、当前页全选、跨页全选的数量正确。
- 设置筛选、看大图、关闭后，筛选和滚动位置保持。
- 大图支持 Esc、左右键、缩放/恢复，关闭时焦点回到原缩略图。
- 常见桌面分辨率下，照片与详情不遮挡；缺字段和损坏图片有明确状态。

### 阶段 C：导出和对外交付（P1）

交付：异步 ZIP、基础 Excel、PDF 模板预览、导出列表、可撤销的集合分享；同时补项目创建/编辑及成员管理入口。

验收：

- “本周 + 指定项目 + 指定成员”的显示数、选择数、导出请求数一致。
- 导出任务可在离开页面后继续，失败可见且可重试。
- 下载包中的数量、目录、命名、时区与配置一致，不静默少文件。
- PDF 中文、长地址、横竖照片混合与空字段均正常。
- 分享撤销、过期、禁止下载都在服务端生效；分享范围不会越过创建者的权限。

### 阶段 D：扩展能力（P2）

地图聚合/卫星/KML/KMZ、更多水印字段台账、项目文档、表单、团队模板、云盘集成、AI 查询逐项推进。每项先验证实际用户需求和 App 端数据配合，避免一次引入大量尚未形成闭环的菜单。

## 6. 首个可评审版本建议

先用一个有照片的项目跑通：**工作区 → 项目卡片 → 项目照片 → 日期/成员筛选 → 大图记录 → 明确选择范围 → ZIP 任务 → 下载。**

这个版本应包括导航、照片工作台和导出任务的必要基础，完成后再扩展 PDF、Excel 和分享。视觉上保留 Timeprint 的橙色强调，统一间距、边框、按钮和密度；不需要复制 Timemark 的蓝色，也不建议第一版常驻 AI 侧栏。

值得保留的现有特点：拍摄记录字段较完整、顶部缩略图有利于快速定位、多语言工具已有基础。值得重点学习的 Timemark 交互：照片优先、项目和成员作为范围、统一筛选、按日期组织、就地完成导出与报告。
